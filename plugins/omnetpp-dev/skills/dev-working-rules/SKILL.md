description: >
  Ground rules for when to act in any software project: nothing is implemented
  without an explicit instruction to implement it, designs need explicit approval,
  and questions are never requests to change anything. Use at the start of every
  task and before every change to code, documentation or configuration.
---

# Working rules

- **Do not implement anything without an explicit request to implement it.**
  Starting implementation requires an imperative from the user that names the
  work ("implement X", "make that change", "go ahead with the refactoring").
- **Designs must be explicitly approved.** A design, plan or proposal is not
  approved until the user approves it in their own words. Silence, a change of
  topic, or a general remark ("back to the code", "OK", "sounds good" about
  something else) is not approval.
- **Questions are not requests to change anything.** A question ("why ...?",
  "what about ...?", "shouldn't it be ...?") is answered, and nothing else
  happens. If the answer suggests a change, propose it and wait.
- **An unanswered question stays open.** Never resolve an open decision
  yourself because the user moved on. Ask again, or list it as open.
- **When in doubt, ask.** If it is unclear whether the user asked for a change,
  they did not.
