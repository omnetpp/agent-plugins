# Generating model documentation with opp_docgen

`opp_docgen` (from the `@omnetpp/opp-tools` npm package) writes a page per NED and MSG type,
with its parameters, gates, properties, inheritance and usage diagrams, a page per source
file, and index pages. The text comes from the `//` comments directly above each type,
parameter, gate and field, so missing or poor docs are fixed in the NED/MSG sources, not in
the output.

Run it from the project root. If `opp_docgen` is not on PATH, or it exits with 127 (a stale
shim of the VS Code extension), use `npx --yes -p @omnetpp/opp-tools opp_docgen …` (needs
Node.js 18 or newer). `opp_docgen --help` lists every option; the points below are the ones
that are easy to get wrong.

## Steps

1. **Pick the format** for where the docs end up:

   | Target | `--format` | Entry page |
   |---|---|---|
   | Standalone website or a local preview | `html` (default), or `html-material` | `index.html` |
   | Pages that should look like a Read the Docs site | `html-readthedocs` | `index.html` |
   | A Sphinx site | `rst` | `index.rst` |
   | A Markdown site (MkDocs, GitBook, mdBook) | `markdown` | `index.md`, plus `SUMMARY.md` |

2. **Pick the output folder** with `-o <dir>` (default `<projectdir>/doc/neddoc`). The folder
   is **managed**: each run deletes the files that the previous run wrote (listed in
   `.neddoc-files`) and does not write again. Files that `opp_docgen` did not write are left
   alone. So use a folder of its own, never a folder that holds hand-written pages that
   share names with generated ones.

3. **Set the NED path** for libraries the project uses (e.g. INET), or their types stay
   unresolved: `--ned-path=<dirs>` (`;`-separated, or `:` outside Windows), else
   `OMNETPP_NED_PATH`, else `omnetpp.nedPath` in the project's `.vscode/settings.json`.
   An unresolved type neither fails the run nor gives a warning, so run `opp_lint` with the
   same NED path first: it reports them.
   Folders on the NED path are **indexed but not documented**; only the project
   directories given as arguments get pages. `.nedfolders` and `.nedexclusions` are honored;
   `-x <glob>` excludes more folders (e.g. `-x 'simulations/**'`).

4. **Link library types** to the library's own docs with `-l <package>=<url-or-path>`
   (repeatable), e.g. `-l inet=../inet-neddoc`:
   - A **path** (relative to the output folder) must point at docs that `opp_docgen`
     generated: it reads their `nedtags.xml`/`msgtags.xml` to find each page.
   - A **URL** is not read; links become `<url>/<package.Type>.html`. For docs generated by
     `opp_docgen`, the type pages are in its `types/` folder, so give the URL of that folder.
   - Library types without a matching `-l` are marked "not documented here".

5. **Run and check** the exit code: 0 means generated, 1 means generated with warnings
   (read them; unlinked library references do not count), 2 means a usage or runtime error.
   Open the entry page and check one type page of each kind (module, network, message)
   before you report the docs as done.

## Options worth knowing

- Diagrams: `--[no-]network-diagrams`, `--[no-]usage-diagrams`,
  `--[no-]inheritance-diagrams` (on by default); the project-wide
  `--full-usage-diagrams` / `--full-inheritance-diagrams` (off by default, large for big
  projects).
- Size: `--no-source-snippets` and `--no-file-listings` drop the source listings.
- `--title=<text>`; `--custom-css=<file>` replaces `style.css` (html formats only).
- C++ links: `--doxytags=<file>` and `--doxy-url-prefix=<url>` link `@class` types to the
  project's Doxygen pages.
- Fragments: `-f <file>` inserts XML `<docfragment>` content at anchors of type, file,
  package and namespace pages (the Eclipse IDE format).

## In a Sphinx site

Generate with `--format=rst` into a folder inside the Sphinx source tree (e.g.
`doc/src/neddoc`), and add `neddoc/index` to a `toctree`. Regenerate before every Sphinx
build: the rst files are build output. Keep the folder out of version control unless the
project already commits generated docs.

## In CI (GitHub Actions)

```yaml
- uses: actions/setup-node@v4
  with:
    node-version: 20
- run: npm install -g @omnetpp/opp-tools
- run: opp_docgen --format=html -o build/neddoc .
```

Then publish `build/neddoc` (e.g. with `actions/upload-pages-artifact` and
`actions/deploy-pages`). To fail the build on warnings, keep the step's exit code; to
allow them, use `opp_docgen … || [ $? -eq 1 ]`. Library sources on the NED path must be
checked out in an earlier step. `@omnetpp/opp-tools` is free for noncommercial use;
commercial use needs an OMNEST license.
