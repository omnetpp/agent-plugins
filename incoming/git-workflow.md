# Git / branch / commit workflow

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- **Commit message convention:** subject = **protocol/area**, then **category** (when not obvious), then description: `IPv6: fix: ...`, `MIPv6: refactor: ...`, `IPv6 ND: feature: ...`, `test: add ...` (test-only commits: area can be just `test`). Categories: `fix`, `refactor`, `feature`, `test`. **Omit `feature:`** when obvious from wording (e.g. subject starts "Implement ..."). Areas seen: `IPv6`, `MIPv6`, `IPv6 ND`/`NDP`, `ICMPv6`, `tcp_lwip`, `TCP`, `test`. Why: history scannable by area and change type. Apply as a **final message-only rewrite** (`git rebase` rewording every commit) AFTER code/history is otherwise final, so earlier rebases don't invalidate it. (commit-message-convention.md)
- **GSD workflow abandoned**: the "get shit done" multi-phase AI workflow was tried (MLDv1 milestone) and judged "too ineffective" — excessive artifacts (`.planning/` tree of phase plans/summaries/reviews + a GSD-enforcing CLAUDE.md) for little benefit. Do NOT propose `/gsd-*` or `.planning/`-style artifacts. Instead: short plan → small green per-stage commits (per commit convention) → verified with fingerprint + module suites (how MLDv2/IGMPv3/PIM were done, and they went better). (inet-gsd-abandoned.md)
- Branch cleanup pattern: reorganize a topic branch into a green-at-every-commit, churn-free history, rebase onto current master, keep a **backup tag** of the old tip (e.g. `topic/ospfv3-serializer-orig`, `bgp-reconnect-graceful-orig`, `topic-mldv1-orig`); verify the clean tip is byte-identical to the old tip over all branch files; run per-commit fingerprints (×2 at change points for determinism). Fold throwaway commits so each example's fingerprint ingredient lands once. (ospfv3-serializer-todo.md, inet-bgp-reconnect-graceful-shutdown.md)
- "Green at every commit" is the standing discipline for multi-stage work: each stage/commit builds release+debug clean and passes the relevant tests/fingerprints before moving on. (ansa-babel-port.md, ansa-isis-port.md, mipv6-tunneling-refactor-plan.md)
- Rebasing a large PR/topic branch onto a much-moved master can be zero-conflict when the touched code regions are disjoint — try the rebase before assuming conflicts. (bgp-pr1110-adjribin-integration.md)
- Third-party PR integration discipline: rebase onto master; evaluate each reviewer comment explicitly (VALID bug / design critique / audit ask) and fix real ones as small behavior-preserving commits; run the full relevant fingerprint suite; do an independent RFC-compliance review (static read against RFC section numbers, distinguishing "simplifications, not bugs") PLUS a **dynamic proof** (run the scenario, confirm the claimed mechanism in the EV log — e.g. a FIB route swap at the expected simtime). A fix commit can be folded into the contributor's commit if a squashed history is preferred (fingerprints stay green either way). (bgp-pr1110-adjribin-integration.md)
- Safety branches before risky cleanup: create e.g. `topic/ansa-isis-precleanup` (= HEAD before final tidy) before ini cleanup/tidying passes. (ansa-isis-port.md)
