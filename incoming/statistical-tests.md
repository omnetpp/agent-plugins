- The opp_repl MCP session crashed on the full ~913-config run (`run_statistical_tests(inet_project)` — too large/streams too much) and was bound to the wrong worktree — its "PASS" results were against the wrong code. Reliable standalone fallback (after `source ./setenv` → correct `INET_ROOT`):
  - **Compare/triage:** `inet_run_statistical_tests -m debug --no-build [-w <dir>]` (CLI, separate process, can't take a session down). Summary line: `N TOTAL, .. PASS, .. FAIL, .. ERROR`.
  - **Record:** NO record CLI exists. One-off script: `from inet.main import *` → `update_statistical_results(working_directory_filter="examples/ospfv3")`. Returns per-config `INSERT`/`UPDATE`/`KEEP`. Records in debug.
  - **Gotcha:** the standalone functions take **no `simulation_project` arg** — set the default first or they raise `Exception: No default simulation project is set`. Either call `determine_default_simulation_project()` at script top (auto-discovers from cwd = worktree root) or pass `simulation_project=inet_project` explicitly. `run_statistical_tests(working_directory_filter=...)` also needs this.
  - `INSERT (unexpected)` is normal for a brand-new config (no baseline yet). `update_*` overwrites on UPDATE, so for a dir with pre-existing baselines, **compare first** (old configs PASS → KEEP, no clobber) before recording the whole dir. (inet-statistical-tests-tooling.md)
- `update_statistical_test_results()` writes a `.sca` baseline ONLY on **INSERT** (no baseline) or **UPDATE** (differs; also drops a `.diff`). On **KEEP** (byte-identical) it writes NOTHING — "no results file generated for sim X" almost always means the baseline already exists and matches (no-op, not a failure). (opp-repl-statistical-keep-no-write.md)
- `StatisticalResultsUpdateTask.run_protected` ALWAYS deletes the temp `examples/<path>/results/*.sca` after each run. Baselines live in `statistics/examples/<path>/<ini>-<config>-#<run>.sca`, NOT the example's `results/` dir (empty by design). The whole `statistics/` tree is gitignored (`.gitignore:24:/statistics`) — baselines never show in `git status` (it's a separate repo). Force regeneration: delete the baseline under `statistics/...` → next update does INSERT. Config selection = `get_simulation_tasks` (every config in scope) — a missing baseline is about run verdict, not skipping. (opp-repl-statistical-keep-no-write.md)
- `.sca` statistical baselines are checksum-value-independent (checksum isn't a scalar). To get Wireshark-valid/serialized traces set `**.fcsMode="computed"` (Ethernet FCS) and `**.checksumMode="computed"`; defaults are "declared" (sentinels), so a pcap run otherwise aborts with "Cannot serialize Ethernet FCS ...". (inet-statistical-tests-tooling.md)
