# Porting-workflow lessons (ANSA → INET; generalizes to any old-INET codebase)

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- **API-translation cookbook**: diff ANSA `src/ansa/routing/eigrp` vs mainline `src/inet/routing/eigrp` (the same code made the 3.4→4.x trip) for a concrete rewrite map: `cPacket`→`Chunk`, `IPv4ControlInfo`/ctrlinfo→tags, `UDPSocket`→`UdpSocket`, `InterfaceEntry`→`NetworkInterface`, `IPSocket::registerProtocol`→`registerProtocol(Protocol::x,...)`, `getModuleFromPar`→`ModuleRefByPar`, `info()`→`str()`, `.oppfeatures` feature entries. EIGRP has no serializer → deferring serializers to a late phase is consistent precedent. (ansa-vrrp-lisp-port.md, ansa-isis-port.md)
- **Phaseable port structure** (used for Babel P1–P6, IS-IS Phases 1–7): (1) defs/constants/value types + module shell + .oppfeatures feature; (2) .msg messages + serializer + round-trip unit test; (3) tables/adjacency; (4) first runnable example (adjacency); (5) flooding/route exchange; (6) SPF/route-install + end-to-end ping example; (7) fingerprints + branch cleanup. Green (release+debug build + tests) at every commit. (ansa-babel-port.md, ansa-isis-port.md)
- **A working example RUN is the verification gate per phase — compile-green is insufficient** (explicit norm: "MUST verify with an actual run — compile-green insufficient"). Each phase's example must actually form adjacency / install routes / deliver pings before committing. (ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **Messages = typed FieldsChunk classes, not raw TLV byte arrays**: TLVs become typed named fields/record arrays per PDU (the EIGRP idiom); L1/L2 message variants collapse to one class with a type field set at build time. Conversion between wire records and working entries lives in one convert layer. Drop non-protocol fields (e.g. ANSA's displayString msg field). (ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **Do ALL protocol setup (configureInterfaces, socket bind, activate) in `handleStartOperation`, NOT split across `initialize()` stages** — `RoutingProtocolBase::initialize` triggers `handleStartOperation` BEFORE the derived class's ROUTING_PROTOCOLS init-stage block runs, so later-stage config comes too late. (ansa-babel-port.md)
- **Prefer one socket + per-packet tags over per-interface sockets**: single `UdpSocket` with `InterfaceReq`/`L3AddressReq` (link-local src) tags replaced ANSA's multi-socket design (Babel); one `Ieee8022LlcSocket` receives from all interfaces (IS-IS). (ansa-babel-port.md, ansa-isis-port.md)
- **Additive node integration — never fingerprint-perturbing**: dormant default-off NED slots (`hasBabel`, activating the existing dormant `llc` hook, `hasMipv6`, `hasIpsec`, `hasPmipv6`); or implement the protocol `like IApp` so it slots into `app[]` with no node-NED surgery (LISP); or a new node type extending `Router` (IsisRouter) leaving `Router.ned` untouched. Prove inertness with byte-identical fingerprints. (ansa-babel-port.md, ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **Dual-stack pattern**: gate per-AF logic on routing-table presence (rt/rt4 vs rt6, e.g. `ModuleRefByPar<Ipv6RoutingTable>`); install `Ipv4Route`+`Ipv6Route` per AF; derive per-AF connected prefixes symmetrically (Ipv4InterfaceData addr+netmask / Ipv6InterfaceData advPrefixes); per-AF hello/adjacency in the neighbour's own family; IPv6-only nodes unaffected. Admin distances are already in INET's shared RouteAdminDist enum (dBABEL=125, ISIS 115, dBGPExternal=20/dBGPInternal=200 mirrored in Ipv6Route). (ansa-babel-port.md, ansa-isis-port.md, inet-bgp-ipv6-check-todo.md)
- **Reuse mainline code instead of re-porting**: ANSA-origin `ClnsAddress` already in mainline (`networklayer/contract/clns`) — don't rename established mainline code; skip dead substrate (ANSA's CLNS module is a hollow LLC relay shim, its datagram path commented out — nothing to port; Integrated IS-IS needs no CLNP plane since PDUs ride the link layer and routes install into the normal IP tables). Parse config XML inline with cXMLElement rather than porting ANSA's `DeviceConfigurator`. (ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **Data-plane capture/re-injection mechanism**: the clean pattern is a TUN interface (as inet `TunnelApp`, applications/tunapp/TunnelApp.cc): route captured prefixes to the tun iface → module receives on a `TunSocket` → encapsulate → UDP send; decap side pops the header and `tunSocket.send()` re-injects into IP forwarding. Alternative: INetfilter hooks returning STOLEN (Result enum = ACCEPT/DROP/QUEUE/STOLEN). Needs a coarse route to the tun iface so cache-miss traffic reaches the module (chicken-and-egg), and the tun iface must have an address (unnumbered-interface local-delivery gotcha). (ansa-vrrp-lisp-port.md)
- **Port fixes latent upstream bugs as you go** and note them (ANSA `LspId` ctors left fragmentId uninitialized; ANSA dangling-ptr in getBestUnicastLocator; ANSA native-forward-drop bug in LISP data plane). (ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **RFC-review + dynamic-proof discipline** (also under Git workflow): static RFC-section-cited code review, marking deliberate simplifications as such, PLUS running the scenario and confirming the mechanism in the EV log; add a targeted example/test for any RFC path that fired 0 times in existing scenarios (BGP explicit-withdrawal path had zero coverage until a purpose-built linear-chain example). Verify regression guards actually fail without the fix. (bgp-pr1110-adjribin-integration.md, mipv6-new-scenarios-plan.md)
- **Widen scenario coverage to flush latent bugs**: a single-topology example (1 MN/1 CN/ping/one handover) hid 8 real MIPv6/IPv6 bugs that multi-CN, multi-MN, TCP-over-handover, two-handover, and return-home scenarios exposed (incl. a CoTI rate-limit timestamp not cleared on handover → RR stall/blackhole, and return-home not de-registering RO from CNs). Looping "dwell-and-dash" TurtleMobility (`<moveto t=..>` in an infinite `<repeat>`, movement.xml via xmldoc) makes phases watchable and surfaced the return-home bug. (mipv6-new-scenarios-plan.md)
