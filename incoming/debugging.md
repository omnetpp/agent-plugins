# Debugging techniques

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- **test.err first** for module-test failures (full rule under Module tests). (inet-test-err-vs-out.md)
- **"Vanishing packet" checklist**: before theorizing about message loss, (1) enable eventlog (`record-eventlog=true`) and look for a DM (delete-message) entry for the packet; (2) check whether test.out is **truncated mid-line** — truncation = the sim CRASHED, not a lost message. A long "vanishing Binding Acknowledgement" hunt was actually a use-after-free segfault on tunnel teardown; also the BA was sent with `sendDelayed(msg, 1, ...)` so analysis windows cut ~1s too early missed it. (mipv6-tunneling-refactor-plan.md)
- **gdb on crashes**: attach gdb to the work-dir `*_dbg` binary directly with `--debug-on-errors=true` — the `inet_dbg` wrapper spawns a subprocess gdb can't see. (mipv6-new-scenarios-plan.md)
- **Qtenv repro**: `cd tests/module/work/<Test> && inet_dbg -u Qtenv omnetpp.ini`, run to the specific event #/simtime identified from the eventlog. (mipv6-tunneling-refactor-plan.md)
- **Log attribution**: run cmdenv with `--cmdenv-log-prefix="@@[%C] "` then `grep -aE "^@@\[(Class)full.path\]"` to attribute lines to modules (examples set no log prefix). (mipv6-new-scenarios-plan.md)
- **Packet-content non-determinism diagnosis**: pcapRecorder on a node, run twice same seed, `cmp` the pcaps; then `tshark -V`/`-x` on the first differing frame. Giveaways: "Packet Length: 0" (a builder that never set the length field) and a garbage tail whose size matches a header-length-constant difference (chunkLength overcounted → serializer pads with uninitialized bytes). **Validate stability at FULL sim-time, not a short window** (bugs may only fire on retransmission). (ospfv3-tnd-nondeterminism.md)
- **Don't trust "fingerprints unchanged" as proof a config-wide change works** — verify per-instance/per-port coverage first. The L2NetworkConfigurator applied its rules to only ONE port network-wide (lazy-compute race: `configureInterface()` called from `interfaceCreatedSignal` during interface creation → `extractTopology()` cached an incomplete topology), which is why changing the default port cost moved NO STP/RSTP fingerprint. Fix pattern: defer per-interface config to `INITSTAGE_NETWORK_CONFIGURATION` (mirror `Ipv4NodeConfigurator`); signal handles only post-init dynamic interfaces. (l2networkconfigurator-one-port-bug.md)
- **Delayed/timed sends widen analysis windows**: check for `sendDelayed()` before concluding a response was never generated. (mipv6-tunneling-refactor-plan.md)
- `InterfaceTable::deleteInterface()` already calls `entry->deleteModule()` — a follow-up `callFinish()`/`deleteModule()` is a use-after-free. (mipv6-tunneling-refactor-plan.md)
- Prefer `findProtocolData<X>()` + null-check over `getProtocolData<X>()` when an interface may legitimately lack that protocol data (e.g. tunnel interfaces have no `Mipv6InterfaceData`; `getProtocolData` throws). (mipv6-tunneling-refactor-plan.md)
