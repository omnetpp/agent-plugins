# Environment / setenv / worktrees

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- **Gotcha:** a fresh shell in `/home/andras/projects/inet` may default `INET_ROOT`/`PATH` to a *different* worktree (observed: `inet-bgp-reconnect`; `which inet` → `inet-bgp-reconnect/bin/inet`). The `tests/fingerprint/fingerprinttest` wrapper runs `$INET_ROOT/bin/inet_fingerprinttest --directory $INET_ROOT`, so tests execute against the OTHER worktree's library while checking this repo's `examples.csv`. Symptom: fingerprint "mismatches" that are really the wrong library being tested (e.g. `Cannot find serializer for Ospfv3HelloPacket`, or computing pre-change values) — looks exactly like a stale/broken build; rebuilding does nothing because the sims never load the local lib. Fix: in **every** Bash command block (shell state does not persist between tool calls), start with:
  ```
  cd /home/andras/projects/inet && source ./setenv -q -r 2>/dev/null; source ./setenv -q 2>/dev/null
  ```
  then verify `echo $INET_ROOT` = `/home/andras/projects/inet`. Only the RUN step is affected (builds are cwd-relative). Same trap applies to any sibling worktree (inet-quic, ansa-*, etc.). Run fingerprints with `-s` (release exe) and `-F tyf`; `-m <regex>` is the line filter, not build mode. (inet-shell-points-at-wrong-worktree.md; also hit per bgp-ospfv3-ipv6-interop-done.md — `export INET_ROOT=/home/andras/projects/inet` before fingerprinttest — and ospfv3-serializer-todo.md)
- **Develop in the main checkout, not a git worktree under `.claude/worktrees/`.** Those directories can be **auto-removed between sessions** (observed: the `ipv6-netfilter-hooks` worktree vanished — `git worktree list` no longer showed it and the dir was gone). Committed work is NOT lost (branch refs + commit objects live in the shared `.git` object store — recoverable via `git log <branch>`, `git reflog --all`, `git cat-file -t <sha>`), but the working tree and any uncommitted changes are gone. How to apply: `git checkout -b topic/X master` in the main repo and work there; commit often so nothing depends on the worktree surviving. This supersedes the "worktree topic/…" patterns in older notes (ipsec-over-ipv6-port, pmipv6-port, ansa-babel-port) for NEW work. (inet-dev-in-main-repo.md)
