# Module tests

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- Filter with **`-f <regex>`** (`--filter`), NOT `-m` — `-m` is **build mode** (`{debug,release}`); `-m 'IPv6_'` errors "invalid choice". `BUILD_AND_TEST.md` §4 shows `-m` as a filter — that is WRONG. Correct: `cd tests/module && rm -rf work && timeout 600 inet_run_module_tests -f 'IPv6_|MIPv6_'`. Other flags: `-w` working-dir, `-c` config, `-i` ini. (inet-test-runner-filter-flag.md)
- Same `-f`/`-m` semantics for `inet_run_unit_tests`. (inet-test-runner-filter-flag.md)
- `inet_run_module_tests` runs the **DEBUG** lib (`out/clang-debug/src/libINET_dbg.so`); `inet_fingerprinttest` (executable `inet`) and the plain `inet` command use **release**. Plain `make` only rebuilds release ⇒ after editing C++, if you only `make` and then run module tests, they execute a STALE debug lib (ghost failures contradicting a clean release build; real symptom: `Unknown parameter 'ipv6TunnelingModule'` from a stale debug lib still calling `par()` for a removed NED param). Build BOTH modes before module tests. (inet-module-tests-use-debug-lib.md)
- Always wrap `inet_run_module_tests` (and ad-hoc sim runs) in the Linux `timeout` command — a buggy change can create an infinite packet loop that hangs forever. E.g. `timeout 600 inet_run_module_tests -f IPv6` (full IPv6/MIPv6 suite ≈90s, so a few minutes is safe); single sim: `timeout 60 inet_dbg ... --sim-time-limit=...`. (inet-module-tests-timeout.md)
- **test.err vs test.out**: the sim's final error/abort message (`ASSERT` failure, `cRuntimeError`, exception, "Error: ..." line) goes to **`work/<Test>/test.err`** (stderr), NOT `test.out` (stdout: EV log, `undisposed object:` lines, `End.`). Grepping only test.out makes a hard abort look like "the sim just stopped / a packet vanished". Debug procedure: `cat work/<Test>/test.err` FIRST. PASS/FAIL comes from the sim's **exit code** (`python/inet/test/all.py`: PASS iff `returncode == 0`), independent of `.test` `%contains`/`%not-contains` assertions — commenting out an assertion can't mask a crash. An **undisposed object does NOT itself force nonzero exit** (warning only) — with exit≠0 and only "undisposed object" in test.out, the real cause is in test.err (the undisposed object is usually a symptom, e.g. a packet orphaned by the aborted event). Running the sim directly with `2>&1` merges stderr so you see the error — that discrepancy vs. test.out is the tell. (inet-test-err-vs-out.md)
- Runner notes: `inet_run_module_tests -m debug --no-build -f "<name-regex>"` (here `-m debug` legitimately selects build mode); its `--dry-run` throws a ValueError — real runs are fine. (inet-module-tests-log-size-cleanup.md)
- opp_test comments must be **`%#`**, not plain `#` — a plain-`#` line is content and silently swallows the next directive; a bare `#` after a `%contains` appends to that block. (mipv6-tunneling-refactor-plan.md, mipv6-new-scenarios-plan.md)
- `.test` idioms: `%contains: stdout` on module-attributed log lines (e.g. `...ipv6.mipv6: ...`); `%subst: /omnetpp:://`; undisposed-object check via `%postrun-command` + `%not-contains`. Tests must stay **independent of examples** — copy networks into `tests/module/lib/` (flat/manual configurator fine there). (mipv6-new-scenarios-plan.md)
- Config matching is **first-match-wins** → put specific per-module log enables BEFORE a `**.cmdenv-log-level=off` catch-all. For a `%not-contains` on a module's line, that module must stay log-enabled or the check passes vacuously. (inet-module-tests-log-size-cleanup.md)
- `.elog`/eventlog tests must keep `cmdenv-express-mode=false` AND log-level on — express=true or log-level=off strips log messages from the eventlog too. (inet-module-tests-log-size-cleanup.md)
- Find the emitting module of an asserted log line with `--cmdenv-log-prefix="%C@@ "` (default prefix is "" so lines are bare). (inet-module-tests-log-size-cleanup.md)
- Log-size hygiene for tests: `record-vector-results = false` everywhere vectors aren't consumed; `cmdenv-express-mode = true` for scalar-only tests (overrides opp_test's generated `_defaults.ini` express=false; one case: test.out 503 MB→4 KB); `**.cmdenv-log-level=off` + re-enable only modules under test + `cmdenv-event-banners=false` for log-asserting tests (3.5 GB→4.6 MB for the MIPv6 family). Overall tests/module test.out went 4.9 GB → 170 MB. (inet-module-tests-log-size-cleanup.md)
- MTU-override gotcha: reducing an Ethernet interface's effective MTU needs `**.<node>.eth[N].**.mtu = 1280B` (trailing `**` matters); plain `**.<node>.eth[N].mtu` silently does NOT apply. (protocol-test-ipv6-suite.md)
- Lifecycle-stage coupling: master inserting `STAGE_NETWORK_INTERFACE_CONFIGURATION` (ModuleStartOperation idx 3, ModuleStopOperation idx 5; getNumStages 8→9) required updating tests printing literal `Doing stage K/8` → `K/9` (Start f(K)=K if K<3 else K+1; Stop f(K)=K if K<5 else K+1). Tests asserting literal stage numbers are fragile to stage inserts. (inet-module-tests-log-size-cleanup.md, bgp-pr1110-adjribin-integration.md)
