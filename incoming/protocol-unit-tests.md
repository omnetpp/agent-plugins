# Unit / protocol tests

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- `tests/protocol/` is a spec-driven black-box conformance framework (`tests/protocol/lib`; suites: wifi, ipv6). Run: `cd tests/protocol/ipv6 && ../lib/build.sh && ./run-tests.sh` (needs `../lib/libprotocoltest.so` built first; opp tools on PATH). (protocol-test-ipv6-suite.md)
- Use opp_test's **`%expected-failure:`** directive for RFC behaviors INET doesn't model: every test asserts the RFC behavior so `%contains` always expects PASS; a NOT-MODELED point fails and is categorized EXPECTEDFAIL (yellow) instead of red FAIL — honest, doesn't fail the run; if INET later implements it, the test flips EXPECTEDFAIL→PASS. (The old `%contains: FAIL` trick is gone.) (protocol-test-ipv6-suite.md)
- **Black-box: observe at the interface (the wire), not internal modules.** SEND = `on("X.eth[0].mac").signal("packetSentToLower")`, RECEIVE = `...packetReceivedFromLower`. At the interface the full Ethernet+IPv6+ND frame is present on BOTH sides, so ND chunk fields AND `ipv6.srcAddress/destAddress/hopLimit` are readable either way. RFCs specify packets on the wire; interface-level observation is robust to host-internal refactors. (Also: the Ipv6 core does NOT emit `packetSentToLower`, so internal send-side observation is awkward.) (protocol-test-ipv6-suite.md)
- Events with no positive packet (DAD success = absence of a defending NA): use scalar signals (`startDad`/`dadCompleted`/`dadFailed`, `.is(1)`) subscribed at the **HOST** level: `on("host1").signal("dadFailed")` — not the ND submodule. INET sends no defending NA while an address is still tentative (only when already assigned). (protocol-test-ipv6-suite.md)
- PacketFilter CANNOT compare an `Ipv6Address` field to a string literal (`ipv6.destAddress == "ff02::2"` fails); use a C++ lambda + support-header helpers (`Ipv6TestSupport.h`: `ipv6Dst`, `isDadProbe`, `nsTarget`, `raHasAutonomousPrefix`, `isSolicitedNodeMulticast`). (protocol-test-ipv6-suite.md)
- `.within(t)` is an **ABSOLUTE deadline** from the step anchor (sim start for step 0), NOT a duration after `.notBefore()` — so `notBefore(3.9).within(6.0)`, never `within(2.0)`. (protocol-test-ipv6-suite.md)
- Timing realism: Redirect fires only after routing settles (~t=10 on a routed net) — use wide windows. Reduce only the *far* interface's MTU so a Packet Too Big returns unfragmented (INET embeds the full original packet instead of truncating to 1280, so a globally-small router fragments its own error). (protocol-test-ipv6-suite.md)
- Standalone opp_test unit-test harness recipe (used for LISP serializer test): `mkdir tests/unit/work; opp_test gen -v X.test; cd work; opp_makemake -f --deep -I$ROOT/src -L$ROOT/src -lINET -o work; make; cd ..; LD_LIBRARY_PATH=$ROOT/out/clang-release/src opp_test run -v X.test` (release lib works, no debug needed; `rm -rf work` after — it's generated). (ansa-vrrp-lisp-port.md)
- Round-trip (serialize→deserialize) unit tests are the ONLY thing exercising the deserialize path — sim receivers keep the chunk object, so `~tNl` only exercises serialize. Always add one per new serializer. (ansa-vrrp-lisp-port.md)
