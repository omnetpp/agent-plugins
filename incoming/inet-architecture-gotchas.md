# Known INET architectural facts worth teaching

*Extracted 2026-07-03 from Claude session memory (`~/.claude/projects/-home-andras-projects-inet/memory/`). Raw material for future INET dev skills — unedited: may contain machine-specific paths and session-specific observations. Source memory file cited per bullet.*

- **Igmpv3 / Mldv2 lockstep**: `src/inet/networklayer/ipv4/Igmpv3.{h,cc}` (RFC 3376) and `src/inet/networklayer/icmpv6/Mldv2.{h,cc}` (RFC 3810) are intentionally near-identical mirrors (Mldv2 written by translating Igmpv3: Ipv4Address→Ipv6Address, IGMP types→MLD-over-ICMPv6, 16-bit response-code codec); host+querier state machines, struct fields, timer kinds, method names line up 1:1. Any behavioral change to one MUST be mirrored into the other in the same session (paired `IPv4: Igmpv3: …` / `IPv6: Mldv2: …` commits). Fingerprint blast radius: only `examples/inet/igmp` (IGMPv3 config) and `examples/ipv6/mld` (MldV2Ssm) exercise them; all other igmp-using examples (pim, multicast, seaport, rtp) run the default **Igmpv2**; `Mldv1` likewise separate — these older-version peers are interop modules, do NOT fold them in. (inet-igmpv3-mldv2-lockstep.md)
- **Protocol registry ordering** affects `~tNlb` of PPP-framed examples — see Fingerprint testing. (inet-protocol-registry-ppp-fingerprint.md)
- **Ipv6NodeConfigurator's `networkConfiguratorModule` defaults to `""`** (unlike Ipv4NodeConfigurator's `"configurator"`) — intentional, MIPv6 needs SLAAC. Any setup wanting Ipv6NetworkConfigurator's computed addresses/routes actually applied MUST set `**.ipv6.configurator.networkConfiguratorModule = "configurator"` — else interfaces silently stay link-local-only ("off-link" errors, hosts with no globals). Recurring trap across the tunnel refactor, GPSR/DYMO-IPv6, Babel port, explicit-address feature. (mipv6-tunneling-refactor-plan.md, gpsr-ipv6-delivery-todo.md, ansa-babel-port.md, inet-ipv6-explicit-address-todo.md)
- **Ipv6NetworkConfigurator won't advertise a prefix (drive SLAAC) across an EthernetSwitch**: with a switched LAN it adds on-link routes but installs no `AdvPrefix` on the router interface (the AdvPrefix block in `Ipv6NetworkConfigurator.cc` `configureInterface` ~line 167 → `addAdvPrefix` ~198 is gated on the router interface's `globalAddress` being set, which doesn't happen across a switch), so RAs carry no Prefix Information option (~32 B), hosts never SLAAC a global. Works with **direct** host↔router links (examples/ipv6/ipv6configurator [Config ManualRouters], RA ~64 B). Workaround: set the router's advertised prefix via its per-node `routes` XML (`Router6.routes` → Ipv6RoutingTable): `<routingTable><local node='router'><interface name='eth0' AdvSendAdvertisements='on'><AdvPrefix AdvOnLinkFlag='true' AdvAutonomousFlag='true' ...>2001:db8:1:1::/64</AdvPrefix><inetAddr tentative='false'>2001:db8:1:1::1</inetAddr></interface></local></routingTable>`. Likely a real configurator bug worth reporting. (inet-ipv6-configurator-switch-noprefix.md, protocol-test-ipv6-suite.md)
- **IPv6 ND/DAD known gaps & bugs** (verified against live traces): RA rate-limiting (`MIN_DELAY_BETWEEN_RAS`) is COMMENTED OUT in `Ipv6NeighbourDiscovery.cc` (~line 1181) — a bug; RFC 4191 Default Router Preference NOT implemented (reserved bits stay 0); `DupAddrDetectTransmits=0` suppresses DAD for the link-local address but INET still sends one DAD probe for the SLAAC global address (RFC 4862 §5.1 says zero disables DAD for every address), and `startDad` still fires when disabled; no gratuitous/unsolicited NA after DAD (RFC 4862 §5.4.4, optional — natural NED param, not a bug); ICMPv6 Packet Too Big carries MTU=0 (`Ipv6.cc` routePacket: `sendIcmpError(pkt, ICMPv6_PACKET_TOO_BIG, 0); // TODO set MTU`) so PMTUD can't converge, and INET does NOT truncate the ICMPv6 error to 1280 B (RFC 4443 §2.4) — embeds the full original packet (both bugs; PTB generation itself works, Ipv6.cc ~1068, `!fromHL` forwarding path); DAD for configurator/manually-assigned addresses intentionally skipped (converged-snapshot model — NOT a gap). (inet-ipv6-nd-findings.md)
- **Ipv6 netfilter hook facts**: only `datagramPreRoutingHook`, `datagramPostRoutingHook`, `datagramLocalOutHook` were originally fired by Ipv6 — `datagramLocalInHook` was NEVER called (Ipv6.cc:251 area) and FORWARD never existed; `reinjectQueuedDatagram()` threw for POSTROUTING/LOCALIN/FORWARD. Completed to IPv4 parity: `fragmentAndSend` (POST_ROUTING), `localDeliverFinish` split from `localDeliver` (LOCAL_IN), `routePacketFinish` (FORWARD, fires only for forwarded `!fromHL` datagrams, stamps routing tags only on QUEUE so the ACCEPT path stays byte-identical). Design principle: the normal datapath was deliberately NOT made packet-only — reinjects reconstruct hook-point args (`fromIE`/`destIE`/next-hop) from tags (InterfaceInd/InterfaceReq/NextHopAddressReq), because Mipv6's LOCAL_OUT hook sets InterfaceReq as a routing *hint* that `routePacket` must keep reinterpreting (packet-only broke 3 MIPv6 `~tNlb`). MAC resolution NOT moved past POST_ROUTING (fingerprint stability; cost: a POST_ROUTING hook can't redirect next hop). Latent reinject bugs found by an all-hooks probe test (`NetfilterHookProbe` in tests/module/lib + `NetfilterHooks_Ipv6/Ipv4.test`, a--r--b, every hook QUEUEs): multicast PRE_ROUTING reinject needs non-null `fromIE`; on-link NA LOCAL_OUT reinject must keep its InterfaceReq/NextHopAddressReq. (ipv6-netfilter-hook-completion.md, mipv6-tunneling-refactor-plan.md)
- **MIPv6/tunneling architecture (post-refactor)**: tunnel = a dynamic virtual `NetworkInterface` (`Ipv6TunnelInterface`, built via `Ipv6RoutingTable::createTunnelNetworkInterface`) + a route, like IPv4 — the old `Ipv6Tunneling` module (4 special gates into Ipv6) is deleted. Old module conflated real IP-in-IP tunnels (HA tunnel) with MIPv6 "pseudo-tunnels" (T2RH = Type-2 Routing Header, HA_OPT = Home Address Option) which are extension-header insertion on route-optimized traffic, not encapsulation (no IPv4 analog, not an interface). Tunnel registry + T2RH/HAO insertion now live in `Mipv6` via its own netfilter hooks (`datagramLocalOutHook` = MN reverse tunnel + T2RH/HAO; `datagramPreRoutingHook` = HA forward tunnel + tunnel-source check + Route-Optimization Event-C trigger); `Ipv6::localDeliver` decapsulates proto-41 generically and re-injects via PRE_ROUTING. RFC 3775: T2RH/HAO are forbidden on mobility-header packets — the LocalOut hook must `if (getProtocolId() == IP_PROT_IPv6EXT_MOB) return ACCEPT;` (without it a BRR got a T2RH and crashed with "Returning an incomplete chunk"). INET previously had NO IP-in-IP tunnel interface (only L2 VirtualTunnel and app-driven Tun+TunnelApp). (mipv6-tunneling-refactor-plan.md)
- **MIPv6 naming (current)**: `xMIPv6`→`Mipv6` (`Mipv6.{cc,h,ned}`), `xMIPv6Support` wrapper flattened into `Ipv6NetworkLayer` (protocol module + `BindingUpdateList` + `BindingCache` direct submodules, each `if hasMipv6`); dirs `networklayer/mipv6`, `node/mipv6`; switch `hasMipv6`; param `mipv6Module`; feature `-DINET_WITH_MIPV6`; instance path `<node>.ipv6.mipv6`. Flattening gotcha: `Mipv6` finds the IPv6 core as sibling `^.ipv6` (was `^.^.ipv6`). Node types (`HomeAgent6`, `WirelessHost6`, `CorrespondentNode6`, `MobileHost6`) set `ipv6.hasMipv6=true` + `ipv6.mipv6.isHomeAgent/isMobileNode`. (mipv6-module-renamed.md)
- **PIM is address-family-generic** (`src/inet/routing/pim/`): one instance per family via `string addressFamily @enum("ipv4","ipv6")`; state = `L3Address`, generic `IRoutingTable`, `IMulticastRoute` + family factory; shared helpers in `PimBase` (`createMulticastRoute`, `findMulticastRoute`, `getMulticastPacketAddresses`, `getMulticastGroupInfo`, `getInterfaceAddress`, `isRoutableMulticastSource/Group`, `encoded{Unicast,Group,Source}AddressLength`). IPv6 PIM uses the interface **link-local** address (RFC 7761) as Hello source/Encoded-Unicast next-hop; ignores link-local-scoped multicast groups via the scope nibble `getMulticastScope() <= 2` — NOT `isLinkLocal()`, which is FALSE for multicast (getScope() returns MULTICAST). SSM (RFC 4607): MLDv2/IGMPv3 INCLUDE(S,G) for a group in the SSM range (`Ipv4Address::isSsm()` 232.0.0.0/8; `Ipv6Address::isSsm()` FF3x::/32; `PimBase::isSsmGroup`) → PIM-SM builds an (S,G) tree directly, no RP/Register; driven by the router-side `ipv4/ipv6MulticastListenerChangeSignal` (carries `*MulticastGroupSourceInfo`, emitted from `Ipv4/Ipv6InterfaceData::setMulticastListeners` — DISTINCT from the host-side `*McastChange` Igmpv3/Mldv2 consume). Embedded-RP (RFC 3956): FF7x::/12 groups (`isEmbeddedRp()`, flags nibble 0x7) carry their RP in the address (`getEmbeddedRpAddress()`); per-group RP via `PimSm::getRpForGroup(group)` set on `route->rpAddr` at creation. Pure-IPv6 node: `inet.node.ipv6.MulticastRouter6`. Real bug pattern: `addNewRouteG` resolved the (*,G) upstream RPF neighbor once at creation — for a directly-connected RP created before the PIM Hello adjacency formed, the neighbor stayed `<unspec>` forever (Join to nobody); fix = handle `pimNeighborAddedSignal` → re-resolve pending routes (`updateUpstreamRpfNeighbor`). Verification gate: the IPv4 PIM example fingerprints MUST stay byte-identical when touching PIM. (inet-pim-ipv6-state.md)
- **BGP architecture**: AF-generalized in the PIM style — one `Bgp` module, `addressFamily` param, runtime `isIpv6()` dispatch; IPv6 NLRI via MP_REACH/MP_UNREACH (RFC 4760) with its own wire (de)serializer; IPv4 keeps its legacy wire encoding (fingerprint invariant). **BGP Identifier stays 4 octets** (RFC 4271/6286) — never generalize `bgpIdentifier`/`routerId` to L3Address; Ipv6RoutingTable has no IPv4 router-id, so IPv6 BGP needs a `routerId` NED param. Shared per-router wildcard `*:179` listener (demux accepted conns by peer addr via `findIdFromPeerAddr`) — a typed IPv6-unspecified bind RST'd incoming v6 conns; plain `bind(TCP_PORT)` (AF-unspecified) accepts both. Active connects must `bind(addr, -1)` — INET TCP only auto-assigns an ephemeral port when `localPort == -1` (`TcpConnectionEventProc.cc:47`); literal port 0 made every active conn `srcAddr:0→peer:179` and two coexisting conns collided in `Tcp::addSockPair`. `ConnectRetryTimer` must be STOPPED on entering Established (RFC 4271) — else it fires ~120 s later and aborts a healthy session. Instant reconnect (even crash-free) livelocks two peers in a re-open/collide ping-pong — a delayed reconnect (`scheduleAfter(connectRetryTime)`) is required. §6.8 collision tiebreak uses INTERFACE addresses, not routerId. `OpenSent::TcpConnectionFails` must stopHoldTimer (the OpenSent "large value" HoldTimer otherwise later kills an adopted connection) and restart (not stop) ConnectRetryTimer. FSM→Idle must stop Hold/KeepAlive/ConnectRetry + withdraw session routes (§8.2.2 Event 18). BGP timers are now `Bgp.ned` params (`connectRetryTime`/`holdTime`/`keepAliveTime` @unit(s) 120/180/60s + `startDelay` 1s); a stray `<TimerParams>` XML element throws — old example XMLs needed migration. No `BgpNotificationMessage` class exists (only the enum); `processChunks` default THROWS on receive, so NOTIFICATION send+receive must land together. (inet-bgp-ipv6-check-todo.md, inet-bgp-reconnect-graceful-shutdown.md, bgp-pr1110-adjribin-integration.md, bgp-timers-to-params-done.md, ospfv3-serializer-todo.md)
- **BGP + OSPFv3 co-existence wiring**: one `Ospfv3Router` (extends `Router`) runs BGP+OSPFv3+IPv6: `hasBgp=true`, `bgp.addressFamily="ipv6"`, `bgp.routingTableModule="^.ipv6.routingTable"`, and CRUCIALLY `bgp.ospfRoutingModule=""` (BGP's redistribution hooks hard-cast to `ospfv2::Ospfv2`). `hasIpv4=false` is fine (OSPFv3's rt4 ref is null-guarded). OSPFv3 runs on Ipv6NetworkConfigurator-assigned addresses (omit `<Ipv6Address>` from its XML). OSPFv3 has NO AS-external-LSA support (full redistribution is research-grade). OSPFv3 convergence ≈51 s with default hello/dead — start test traffic after (ping at t=70s). BGP-over-IPv6 needs: defer iBGP session start until the IGP installs a route to the peer; use generic IRoute (not Ipv4Route casts); MP_REACH next hop = self on-link address for locally-originated routes; resolve the multi-hop BGP next hop recursively via the IGP (`getNextHopForDestination`) before installing. (bgp-ospfv3-ipv6-interop-done.md)
- **OSPFv3 bugs**: (fixed) `Ospfv3Area::originateRouterLSA()` never set `lsaLength` (deserializer derives router-entry count from it → malformed); (fixed) `Ospfv3Neighbor::retransmitUpdatePacket()` computed LSU length as `OSPFV3_HEADER_LENGTH + OSPFV3_LSA_HEADER_LENGTH` (16+20) instead of header + 4-octet "# LSAs" field (16+4) → chunkLength overcounted by 16 → serializer padded 16 uninitialized run-to-run-varying bytes = the `~tND` non-determinism; also that builder left the packet-length header field 0. (Open) every OSPFv3 Router-LSA originates with 0 router entries — routers don't advertise transit/p2p links; SPF can't build topology from Router-LSAs (examples converge enough to route anyway); investigate DR-election/FULL-state timing at `Ospfv3Area.cc` ~711-755. Also (pre-serializer): broadcast/multi-area `~tND` was non-deterministic because LSA contents (e.g. Network-LSA attached-router lists) were emitted in unordered-container order. (ospfv3-tnd-nondeterminism.md, ospfv3-serializer-todo.md)
- **IPsec (dual-stack)**: `src/inet/networklayer/ipsec/` (moved from ipv4/), namespace `inet::ipsec`; a netfilter hook (egress = POST_ROUTING QUEUE for the delay model, ingress de-protection = LOCAL_IN), transport-mode AH/ESP, no real crypto. Dual-stack via: `PacketInfo`/`PacketSelector` on `L3Address` (`rangelist<L3Address>` rewritten with `operator<` only — L3Address lacks `<=`); family chosen **per-instance** from a `networkProtocol` NED param ("ipv4" default; "ipv6" set by the IPv6 layer) — NOT from `NetworkProtocolInd` (that tag is ABSENT at the egress POST_ROUTING hook; Ipv4 only sets it on ingress); header reads via `NetworkHeaderBase` (`getSourceAddress`/`getDestinationAddress`); only real per-family divergences: protocol-id field, length-field semantics (Ipv4 `totalLength` incl header vs Ipv6 `payloadLength` excl 40B base), trailing L2 padding — handled by file-static `dynamic_cast` helpers. AH/ESP stay opaque `FieldsChunk`s (no IPv6 ext-header serializer). Latent AH bugs (AH had NO example/fp coverage): egress — `IPsecAuthenticationHeader` had no `chunkLength` → 0-length FieldsChunk made `insertAtFront()` throw "chunk is empty" (fix: `chunkLength = B(IP_AH_HEADER_BYTES)`, constant corrected 24→12, ICV is a separate trailing chunk); ingress — AH header removed TWICE (2nd `removeAtFront` hit the `EncryptedChunk` → crash). `isIpv6ExtensionHeader()` must NOT treat AH(51)/ESP(50) as walkable IPv6 extension headers — Ipv6::localDeliver's fragment-detection chain walk (runs BEFORE the LOCAL_IN hook) crashed peeking an `IPsecEspHeader` as the stub `Ipv6EncapsulatingSecurityPayloadHeader`; AH/ESP terminate the chain, IPsec strips them. Multicast egress: `getRemoteAddress().isMulticast()` bypass is family-agnostic. `hasIpsec` + ipsec/spd/sad submodules in `Ipv6NetworkLayer.ned` mirror Ipv4NetworkLayer + Mipv6. (ipsec-over-ipv6-port.md)
- **PMIPv6 (RFC 5213)**: one `Pmipv6` module, both roles via params `isLocalMobilityAnchor`/`isMobileAccessGateway`. PBU/PBA = MIPv6 BindingUpdate/BindingAcknowledgement EXTENDED with a P-flag (bit 0x0200 in BU flags / 0x40 in BA) + proxy options (MN-Id NAI, home network prefix+len, handoff indicator, access-tech type, timestamp); serializer writes proxy fields ONLY when P-flag set → plain MIPv6 BU/BA stay byte-identical. MAG identifies the access link from the L2 signal source via `getContainingNicModule` — NO ieee80211 type dependency (per-access-interface XML policy profile `mobileNodeProfiles`). LMA binding cache is an embedded std::map keyed by MN-NAI (not a separate module). Shared MAG↔LMA IPv6-in-IPv6 tunnel per serving MAG via `Ipv6RoutingTable::createTunnelNetworkInterface()`; home-network-prefix routed into it, re-pointed on handover. Added public `Ipv6NeighbourDiscovery::sendUnsolicitedRa(ie)` so the MAG advertises the home prefix immediately after PBA. (pmipv6-port.md)
- **L2NetworkConfigurator one-port bug (fixed)** — see Debugging; also fixed alongside: `getIndex()` on scalar host gates, and BFS traversal cut off at already-matched interfaces; `dumpConfiguration` param + `tests/module/L2NetworkConfigurator_1.test` added. Uniform cost scaling (1→20000) preserves STP path-cost ORDER → ieee8021d fingerprints stayed byte-identical. (l2networkconfigurator-one-port-bug.md)
- **GPSR/DYMO-over-IPv6 delivery limits**: IPv6 ad-hoc/MANET suffers an emergent congestion storm vs IPv4: (1) ICMPv6 Redirects fired on every forward in a single-/64 ad-hoc link (every GPSR forward goes back out the same interface → `Ipv6::routePacket` fires `nd->sendRedirect` per RFC 4861 §8.2; IPv4 sends NO redirects — Ipv4.cc has no such block) — fixed with a new `bool sendRedirects` param on Ipv6 (default true; set false for MANET); (2) IPv6 ND (address resolution + NUD churn) congests a shared wireless medium far more than ARP; (3) `Ipv6` correctly refuses to forward link-local destinations ("link-local doesn't get forwarded") — why link-local-only MANET-IPv6 can't work multi-hop, and why MANET examples need a global prefix + node-configurator wiring. Even fixed, GPSR-IPv6 delivers ~2/17 vs IPv4 ~8/17 — parity is research-grade. (gpsr-ipv6-delivery-todo.md)
- **Router/host module wiring switches worth knowing**: `Router` defaults `hasUdp=false` (set it for UDP-using protocol nodes, e.g. LISP); `Router`'s `*.routingTableModule` wildcard forces the ipv4 path — an IPv6-only routing protocol must override per-instance in the ini (e.g. `isis.routingTableModule=""` + `routingTableModule6="^.ipv6.routingTable"`); `LinkLayerNodeBase` has a dormant `llc: <default("")> like IIeee8022Llc` slot — activate with `llc.typename="Ieee8022Llc"` + `llc.registerProtocol=true`. (ansa-vrrp-lisp-port.md, ansa-isis-port.md)
- **INET local-delivers packets arriving on an UNNUMBERED interface** (Ipv4.cc fromIE getIPAddress isUnspecified) → a TUN interface used for capture/re-injection MUST have an address. (ansa-vrrp-lisp-port.md)
- **Configurator `<interface towards='...'>` fails across an L2 switch** (fails to assign the address to the intended interface) — use `names='ethN'` on a switched LAN. Host default routes: `<route destination='0.0.0.0' netmask='0.0.0.0'>`; IPv6 `<route gateway=...>` not `nextHop=`. With `addRemoteRoutes=false`, `addDefaultRoutes` breaks for IPv6 hosts — give hosts defaults via RA instead of manual `<route>`. (ansa-isis-port.md, ansa-vrrp-lisp-port.md, ansa-babel-port.md)
- **Ipv6RoutingTable has NO global connected routes** (only fe80::/10) — protocols needing connected prefixes must derive them from `Ipv6InterfaceData` advPrefixes/global-addresses, NOT the routing table (asymmetric with IPv4). IPv6 global addresses are assigned only after DAD (~0.5 s runtime) and only if the node configurator is wired (see networkConfiguratorModule above). (ansa-babel-port.md)
- **`network` is a reserved NED keyword** — an example directory named `network` breaks the package declaration (use e.g. `routing`). (ansa-isis-port.md)
- **msg-file rules**: OMNeT++ msg `struct`s CANNOT have dynamic array fields — any record with a variable-length array must be a `class`; struct fields are PUBLIC members (`lr.rloc`), class fields use getters (`rec.getEidPrefix()`). Embed hand-written value types via `@existingClass @opaque @toString(.str())`. (ansa-isis-port.md, ansa-vrrp-lisp-port.md)
- **Serializer byte count MUST equal chunkLength** — update every builder's chunkLength formula to match the serializer exactly (including always-present count bytes); for variable-length messages add wire-length helper functions the send methods call via `setChunkLength()` before `insertAtBack()` so the FieldsChunkSerializer length check holds. Guard `setChunkLength` with `isMutable()` when resending reused immutable chunks. B-unit gotcha: `B(x).get()` returns BYTES not bits. (ansa-isis-port.md, ansa-vrrp-lisp-port.md, ansa-babel-port.md)
- **VRRP integration pattern**: ONE gateway module (`Vrrp`, RoutingProtocolBase, owns ipIn/ipOut, parses XML, dynamically creates per-VR submodules, demuxes proto-112) + GATELESS `VrrpVirtualRouter` submodules driven by C++ calls (parent→VR `processReceivedAdvertisement()`; VR→parent `sendAdvertisement()` via `Enter_Method`) — keeps per-VR @statistic/WATCH + own timers. Virtual-MAC takeover via an additive default-inert `VirtualForwarder` list on NetworkInterface consumed by 4 guarded hooks: `matchesMacAddress` + `EthernetMacBase::dropFrameNotForUs` (L2 accept), `InterfaceTable::findInterfaceByAddress` (isLocalAddress → ARP target + ICMP-to-VIP), `Arp::resolveMacAddressForArpReply` (reply with virtual MAC). Inertness proven by 790 byte-identical fingerprint runs. (ansa-vrrp-lisp-port.md)
- **IS-IS-over-LLC facts (proven)**: EthernetEncapsulation + Ieee8022Llc coexist fine on one interface (IPv4 via ethertype, IS-IS via LLC SAP 0xFE). OSI multicast MACs AllL1ISs `01:80:C2:00:00:14` / AllL2ISs `01:80:C2:00:00:15` are NOT predefined in `MacAddress.h` — define them + `ie->addMulticastMacAddress(...)` per interface. Send = Packet + `Ieee802SapReq`(ssap=dsap=0xFE) + `MacAddressReq`(multicast) + InterfaceReq via `llcSocket.send()`; receive via `Ieee8022LlcSocket::ICallback::socketDataArrived`. `Ieee8022LlcSocket::sendOut` auto-adds DispatchProtocolReq/Ieee802SapReq/InterfaceReq from stored saps; `open(-1, 0xFE, 0xFE)` (localSap only) gets one socket receiving from ALL interfaces, egress iface set per-packet via InterfaceReq. ProtocolGroup already maps 0xFE00→`Protocol::isis`; `isisAdjChangedSignal` already in Simsignals.h. (ansa-isis-port.md)
- **Link-state SPF next-hop for IPv6 should be the neighbour's GLOBAL address, not link-local** — link-local next-hops didn't forward cleanly in INET (IS-IS port finding). Contrast: PIM's Hello source/adjacency uses link-local per RFC 7761 — protocol adjacency source ≠ route next-hop, don't conflate. Also: an SPF first-hop inheritance branch must propagate BOTH per-AF next hops (a v4-only propagation gave 2-hop IPv6 routes an unspecified next hop → routing loop while IPv4 worked). (ansa-isis-port.md)
- **Flooding protocols need explicit DB sync on adjacency-up**: fire-and-forget flooding alone misses LSPs received before an adjacency formed — on adjacency UP, flood the whole LSDB to the new neighbour (`sendDatabaseToInterface()`). (ansa-isis-port.md)
- **Wireless shared-medium sends need batching + jitter**: one packet per protocol event at the same instant triggers radio "another transmission already started" errors — batch per-(dst,iface) TLVs into MTU-split flushes, and jitter the flush delay (`*= uniform(0.5,1.0)`) so nodes don't flush at the same instant. (ansa-babel-port.md)
- **Ipv4NetworkConfigurator refuses /32 host addresses on a shared wireless link** ("Failed to find address prefix"), and a /24 makes all nodes on-link — multi-hop MANET addressing needs the protocol to advertise /32 host routes itself. (ansa-babel-port.md)
